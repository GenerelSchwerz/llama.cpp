# GenerelSchwerz fork feature guide

This guide documents the user-visible features and internal backend integration carried by this maintained fork relative to its `llama/dev` baseline.

## CUDA MoE expert cache

The expert cache keeps a configurable number of routed MoE expert slabs in GPU memory and pages cold slabs from host memory. It is opt-in and CUDA-only. Grouped decode uses frequency-aware eviction with LRU tie-breaking by default; prefill and the legacy cache retain their existing policies.

Frequency history ages by one halving every 16 grouped planning steps, so previously hot experts do not stay protected indefinitely. This changes cache replacement, not expert routing, tensor values, or compute kernels. It uses small per-expert counters rather than extra expert slots. Set `GGML_CUDA_MOE_FREQUENCY=0` before starting the process to use LRU replacement in grouped decode; omit it or set `1` to restore the default. The setting is fixed when the CUDA grouped context is created, including for captured graphs.

| Public control | Default and disable behavior | Effect |
| --- | --- | --- |
| `--moe-expert-cache-size N` or `LLAMA_ARG_MOE_EXPERT_CACHE_SIZE=N` | `0` by default; set `0` or omit it to disable; negative values are rejected | Keeps `N` expert slabs per cached expert tensor on each owning CUDA backend. This is not a process-wide total. |
| `--moe-expert-cache-mib MiB[,MiB,...]` or `LLAMA_ARG_MOE_EXPERT_CACHE_MIB=...` | Absent by default; mutually exclusive with a nonzero cache size | Converts one broadcast budget, or one budget per selected device in device order, into the largest owner-local slot count that fits. Every device owning selected cache layers must fit at least one slot. |
| `--moe-expert-cache-layers N[,N-M,...]` or `LLAMA_ARG_MOE_EXPERT_CACHE_LAYERS=...` | Absent by default | Restricts caching to complete routed expert groups in the listed zero-based layers and enables residual placement precedence: explicit tensor/CPU overrides win, then the cache claims selected expert tensors left over. |
| `--spec-draft-moe-expert-cache-size N` or `LLAMA_ARG_SPEC_DRAFT_MOE_EXPERT_CACHE_SIZE=N` | `0` by default; set a positive value to enable caching for a separately loaded draft model | Sets the expert cache size for a speculative draft model without changing target-model placement. |
| `--spec-draft-moe-expert-cache-mib` and `--spec-draft-moe-expert-cache-layers` | Absent by default | Draft-model equivalents of the target byte-budget and layer-selector controls. They remain independent when a separate draft model is loaded. |
| `llama_model_params::moe_expert_cache_slots` | `0` from `llama_model_default_params()` | Library equivalent of `--moe-expert-cache-size`; set it before loading the model. |
| `llama_model_params::moe_expert_cache_byte_budgets` and `moe_expert_cache_layer_ranges` | `NULL`/`0` from `llama_model_default_params()` | Borrowed-array library equivalents. The model copies both arrays during construction. Byte budgets are bytes, not MiB. |
| `--moe-expert-cache-host-pinned-mb N` or `LLAMA_ARG_MOE_EXPERT_CACHE_HOST_PINNED_MB=N` | `0` by default tries full pinning, then automatically registers complete groups after pageable fallback; negative values are rejected | A positive value bounds model-wide pinned staging, auxiliary sources, and retained complete experts in MiB. The main expert cache must also be enabled. |
| `--experimental-logs` | Off by default; omit it to disable | Enables detailed experimental CUDA MoE cache, matrix-dispatch, grouped-execution, and page-residency logs. It has no environment alias. Basic hit, miss, eviction, and hit-rate summaries remain available without it. |

When enabled without `--moe-expert-cache-layers`, the loader preserves the legacy contract: it prepends a cache placement override for routed `ffn_up`, `ffn_down`, `ffn_gate`, and fused `ffn_gate_up` expert weights, including chunk-expert names. This override wins over matching `--cpu-moe`, `--n-cpu-moe`, and user tensor buffer overrides. With an explicit layer selector, user tensor and CPU overrides run first and the cache claims only the selected routed weights left over. A selected source group must place all of its routed banks in the cache; partial groups fail model loading instead of silently mixing execution paths. Shared experts, dense FFNs, and unrelated tensors keep their normal placement. On a build without CUDA, an enabled cache is rejected because its requested placement cannot be honored.

Without a host budget, cold weights use pinned host memory when possible and memory-mapped models page directly from their mapped source. After an allocated source fails full pinning, grouped execution reserves its pinned staging requirement, attempts complete expert groups in model order, and retains each registration that CUDA accepts. A source that spans separate registrations uses staging because one device alias cannot address it safely. Remaining groups use pageable staging. `GGML_CUDA_NO_PINNED` disables automatic registration and uses pageable host backing while retaining CUDA cache ownership. Unexpected pinned-allocation failure logs a warning. With a positive host budget, mandatory staging and auxiliary sources are reserved first. The remaining capacity is divided across groups for retained complete expert sets; bounded mode does not register whole base groups in model order. Grouped decode reuses retained experts after GPU eviction and copies only host-cache misses from the source backing. A budget below the mandatory working space is rejected. Mandatory space follows the actual retained allocation families for each pageable group: grouped materialization, legacy per-bank scratch, and independent grouped-host-staged per-bank scratch. Retained slots and early-router prepack storage remain optional growth. The pinned budget does not include the model's ordinary host or mmap backing; retained slots duplicate source bytes within the cap. Embedders set `llama_model_params::moe_expert_cache_host_pinned_size` in bytes before loading the model. This replaces the former mmap-only L2 setting; there is no independent L2 budget.

With the default host budget (`0`), pageable expert banks from mmap/DIO or a failed full-pinned allocation also support grouped materialization. Each CUDA backend registers its own source descriptors and reserves one expert tile plus plan/control storage per eligible group, with at most 64 MiB of additional pinned staging for batching and prediction. Staging is allocated on demand and retained by graph resource leases; model source pages are not registered by this path. Explicit nonzero host budgets use the same cap accounting. `GGML_CUDA_NO_PINNED` forbids this staging as well: required-grouped workloads still fail if their sources cannot be materialized. Existing kernel, routing and auxiliary-source eligibility checks remain in force.

Eligible pageable contiguous F32 expert scales and biases use original-ID GPU shadows for both slot gathers and certified original-ID consumers, including grouped host-staged execution. These copies have a separate fixed 32 MiB limit per backend context, shared across its groups and retained generations. Mapped/device auxiliaries are not duplicated. This extra memory is accounted separately from expert slots, pinned staging and prefill auxiliary storage; exceeding the limit or failing allocation declines execution without legacy fallback for required-grouped graphs. Published model contents are immutable: synchronize and republish candidates after changing their values or backing. Resource leases retain old shadows until pending work ends.

GPU memory use scales with the owner-local slot count times the expert-slab stride for every cached expert tensor assigned to that device, plus metadata and eligible auxiliary storage. Model finalization asks the owning backend for fixed/per-slot allocation sizes, so CUDA row padding, grouped planner state, debug counters, and early-router workspace follow the same backend definitions as runtime allocation. `--moe-expert-cache-mib` derives each owner's slot count from the aggregate target plus active MTP-context ledger, capped by the model's expert count, and `--fit` attributes each context's share without charging the shared model twice. Auxiliary shadows and prefill copies are conservative upper bounds because runtime aliasing can avoid them; this may under-fill a budget but must not choose a slot count whose accounted allocation exceeds it. A positive host-pinned budget contributes the three mandatory staging families to the host-memory breakdown and is rejected before loading if they cannot fit. Cache allocations remain independent per owner; this is not a shared multi-GPU arena.

Cache misses, eviction protection, sibling prefetch, bounded overflow staging, cached prefill MMQ/MMVQ dispatch, and CUDA graph capture/replay are automatic implementation details. Eligible small contiguous F32 expert biases can remain GPU-resident for prefill under a fixed 32 MiB candidate-table budget. A fresh model load may place complete routed groups ordinarily next to residual cached groups; each group keeps its existing owner and execution path. Grouped decode is also automatic: it accepts certified target-model decode graphs with independent rows, including `-np 1` and parallel one-token-per-sequence batches, when the complete expert group and CUDA kernel capabilities match and the total routed experts fit in `N` slots. Unsupported layouts, types, graph shapes, mixed prompt/decode batches, incomplete manifests, active LoRA, tensor overrides, insufficient slots, and unavailable optimized kernels fail closed to the existing cached `mul_mat_id` path. Setting the cache size to `0` restores baseline model placement and execution.

A separately loaded speculative draft model starts with expert caching disabled. Set its size or byte-budget option to enable it without changing target-model placement; its optional layer selector is also independent. The default keeps normal draft placement, so `--spec-draft-ngl all` can keep an eligible draft model entirely on the selected GPU. MTP without a separate draft file uses the target model's weights and target cache controls. Target, separate-draft, and MTP contexts have distinct execution namespaces. Certified supported speculative graphs use grouped execution; unsupported speculative shapes fail closed according to their required-grouped contract rather than being described as target-only. The cache does not change sampling controls: target `-bs`/`--backend-sampling` remains opt-in and off by default, request-local `backend_sampling: false` and its CPU fallbacks remain intact, and draft/MTP sampling defaults are unchanged.

All CUDA devices can consume the cache buffer type and cache resources are owned by the CUDA backend context for the device that executes a layer, so normal layer-split placement can use device-local caches. The cache override is not a CUDA split buffer: row- and tensor-split sharding of matched expert weights is not implemented or covered by this fork's cache tests. Tensor split with a nonzero expert cache is rejected before weight allocation because the tensor-mode meta backend cannot consume the cached buffer. Use layer split or set the expert cache size to zero for tensor split.

Stage A explicitly places complete eligible grouped regions on their layer owner before runtime/reserve scheduling. See [grouped MoE multi-GPU validation](moe-grouped-multigpu.md) for the physical two-device fixture, no-P2P transfer path, owner-local diagnostics and hardware validation status.

The server prints and resets aggregate cache statistics at request timing boundaries and model unload. With parallel requests, this is a process-wide reset boundary rather than strict per-request attribution.

### Internal backend integration

The fork resolves MoE buffer operations, cache statistics and typed expert manifests through `ggml_backend_reg_get_proc_address()`. The internal procedure declarations and snapshot layouts live in [ggml-backend-moe.h](../ggml/src/ggml-backend-moe.h), not the installed public backend headers. Deploy matching fork-built executables and llama/ggml/CUDA libraries; these private procedures are not a stable API for mixing builds.

The llama runtime publishes complete V2 candidate snapshots and refreshes them after LoRA changes. Rejected, incomplete or unknown snapshots are ineligible for grouped execution. Snapshot arrays are borrowed for the call; tensor pointers in an accepted snapshot remain valid until replacement. Buffers and active cache resources retain the bounded host-budget owner.

## Generic fork helpers

- Graph execution certificates: `ggml_graph_execution_certificate` describes MAIN, DRAFT, or MTP ownership and independent, sequential, or speculative row semantics. Pass it with `ggml_backend_sched_graph_compute_ext()` or `ggml_backend_sched_graph_compute_async_ext()`. Invalid or absent certificates run as ordinary uncertified graphs. The scheduler stamps source and split graph IDs only for each backend compute callback; a backend must validate and copy needed fields synchronously and must not retain the certificate address. Existing scheduler compute APIs are unchanged. The llama runtime automatically certifies eligible independent decode batches.

- Draft context namespace: `LLAMA_CONTEXT_TYPE_DRAFT` distinguishes a separate speculative draft context from the default target and `LLAMA_CONTEXT_TYPE_MTP` contexts. Common speculative setup assigns it automatically; the default context type and MTP behavior are unchanged.

- Dense penalty counts: the penalties sampler automatically uses a vocabulary-sized dense count table for valid token IDs, with a map fallback for out-of-range IDs. This has no flag or API change and preserves repeat, frequency, and presence penalty semantics, including duplicate candidate IDs, reset, and clone behavior.
