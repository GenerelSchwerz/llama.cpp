# Complete expert-body waves

Status: complete-body model replay is implemented and passes bounded numerical/path tests in attempt30. Serving performance and matched-resource qualification remain open. Later sections record the progression; earlier per-projection-only descriptions are historical.

## Existing contracts and the actual barrier

The graph already owns route identity, tensor geometry, ordinary arithmetic and external readers. The canonical grouped owner already owns expert slots, source leases, maps, staging storage and release events. Keep these authorities.

Current source preparation selects routed projections for certified prefill and rejects non-projection experts (moe-source-core.cu, core_session::allocate). replay_prefill consequently executes a separate prelude, ID readback, host plan and execute_bounded_prefill call per projection. execute_bounded_prefill prepares one upstream MMQ input and runs its expert ranges before returning. ggml_cuda_mmq_mmid_prepare_impl groups routes and quantizes the entire projection input before any ranges run (mmq.cu:839-931).

That last contract prevents directly moving the current down-projection preparation inside the first gate/up wave: the remaining hidden rows do not exist yet. Reordering only the existing calls would read uncomputed hidden values. Removing completion waits alone does not create complete expert groups.

ggml_moe_source_body::compact already describes private route-axis tensor clones and checked upstream operators. Its input gather is currently a host helper; compact body metadata is not currently the certified prefill execution interface. Reuse and extend these contracts rather than copying a model's expert implementation.

## Proposed execution unit

1. Find consecutive routed regions with the same logical IDs and route geometry in one backend split. Use graph dependencies and use counts to find a route-local body connecting their dynamic inputs and outputs. Require the same canonical owner and compatible source leases. Do not use model names, fixed dimensions or fixed expert counts.
2. Count routes once for that body and retain a unique original scatter destination for every route, including repeated expert IDs within one token. Group expert IDs according to the actual byte budget. Route order within a group is stable and explicitly mapped back to the original output order.
3. Gather the body's dynamic inputs with upstream GET_ROWS and checked shape views. Compact private operator metadata to the selected routes. Keep original tensors, quantization blocks, strides, precision parameters and auxiliary readers unchanged. The weight sources remain original witnesses owned by the canonical owner.
4. Stage the required banks for the same expert group under the existing owner. Run the body's original MUL_MAT_ID, bias, activation, scale and down operators on the compact route group. Quantization sees only ready hidden rows. A later MMQ extension may share route preparation or quantized input between compatible projections; it must preserve the selected upstream arithmetic contract.
5. Scatter every live output, including externally read intermediates, through upstream SET_ROWS into the program's original private tensor layout. The destination set must be proven unique before launch. Publish public outputs only after all groups and state effects finish.
6. Use the existing owner copy-ready and release events to overlap the next group's transfers with current compute. The owner retains all source leases until the last reader completes. Cross-layer copy-ahead is a subsequent extension of the same owner queue, not a profile predictor or another residency authority.

The initial production implementation should keep existing projection execution inside mandatory hybrid for a body that cannot be safely segmented. This is a scheduling choice based on dependencies, operator semantics and budget, not a model support tier or ordinary-executor fallback. Unknown route-mixing operators must retain their full upstream dependency ordering. Fast segmentation must not become the definition of model support.

## Smallest interface extension

The source program should own the checked combined cut and its compact body metadata. Keep a full-size private output for each live value so that existing ordinary consumers and publication remain unchanged. The owner should expose a scoped wave of its existing prefill arena to that prepared body, with validated original bank bindings, one source map and per-bank resident/staged views. A callback submits the original operators before the owner records the wave's release event. Do not create another arena, weight catalog or eviction policy.

The current execute_bounded_prefill call cannot be repeated unchanged on compact tensors: its source-binding validation requires the original projection's complete input/output geometry. The necessary extension must validate the compact tensor relationship through the prepared source body and original witness, rather than weakening those checks for arbitrary tensors. Its existing mapped-MMQ and generic original-format paths remain the arithmetic dispatch contracts.

Reserve compact metadata, gather/scatter maps, ready-row capacity and temporary tensor storage before execution. Rebind only the active route extent inside that capacity. Charge every simultaneously staged bank and quantized padding to the same64MiB lane budget. At the reference pack's largest2,329,600-byte complete expert,64MiB holds at most28 whole experts before other alignment or padding charges; this is an example derived from data, not a production group-size constant. Bank layouts with different sizes derive their own bound. A body that cannot fit one complete expert must retain valid bank-wise execution within mandatory hybrid.

Preparing a new full-input down MMQ at the start of the body is invalid because its hidden input is not ready. Preparing a compact down operator after that group's activation is valid. Sharing quantized gate/up input or a prepared route image is a separate optimization after numerical equivalence; it must not require an independent arithmetic implementation.

## Retain prepared root projections in the frame

Source inspection of mmq.cu:839-931 shows an important performance constraint. The original producer uses dedup_bcast when one activation row feeds multiple routes; quantize_scatter_mmq_q8_1_cuda quantizes original token rows before scattering. Compacting every root activation into one row per route removes that condition and repeats quantization across routes. Do not discard this upstream optimization when integrating the frame.

Identify root routed projections by their activation being outside the prepared cut, rather than by gate/up names. Prepare those original full-size producers once after their prelude and original IDs are ready. Each owner wave launches their original expert ranges into the full private outputs. Gather only those ready output rows for the compact activation/intermediate/down body. This preserves original producer dispatch and broadcast quantization; internal projections prepare only after that group's input becomes ready. A root projection that is also a live output already has its full original result and does not need redundant scatter. Non-root live outputs still scatter to the original private layout.

Extend allocation dependencies for both external inputs and full root-projection outputs through the final body projection. Keeping only inputs alive is insufficient: otherwise later full-size outputs may reuse root output storage, and a subsequent group's root write could corrupt previously scattered results. Require checked flattenable route strides for gather views; do not copy an entire partially ready output just to flatten it. Unsupported segmentation retains the existing mandatory hybrid projection schedule.

Root prepared objects hold compute-pool buffers across the body. Include their simultaneous persistent requirements plus the largest compact operation and route map in the existing resource plan before execution. Destroy prepared objects in reverse allocation order after their last readers are ordered. Use shared sequential gallocr plans for the maximum compact workspace, not one worst-case buffer per model layer.

Bind auxiliary read-only sources through program.find(original), which already preserves canonical leaf leases and device views. Wrap external data as leaf metadata so building compact gather/scatter graphs cannot traverse and execute the main program again. Reuse upstream GET_ROWS, views, ordinary operators and SET_ROWS. Preserve explicit metadata-versus-write classification and the original MMQ/generic consumer contract; a smaller compact extent must not silently switch precision or kernel selection.

Next connect this prepared frame to the new owner callback in replay_prefill. Preserve profile observations, per-projection completion accounting, cancellation/publication and all-GPU partitioning. Then qualify full numerical paths and matched actual staging/workspace/resident budgets before serving comparisons.
