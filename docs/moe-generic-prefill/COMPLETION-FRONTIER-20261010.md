# Reuse the next prefill completion frontier

## Source-backed question

Current source replay_prefill_body waits for the complete stream after all body waves, then replay_prefill immediately submits the next layer prelude, copies its router IDs and waits for that same stream again. The final layer also has an epilogue/publication completion frontier. Strata submits group products and event-controlled ring reuse without this host body barrier. The measured addressing difference is real, but whole-body grouping, root-only grouping, blanket packing and pointer substitution did not establish a general fix. Investigate this existing completion contract separately from packet architecture or cached sampler graphs.

## Smallest possible change, not implemented

Keep original body eligibility, operators, kernels, quantization, scratch bounds and canonical owner. Separate body enqueue from completion accounting. For calls without a test hook, retain one local pending-body pointer in the replay function. Submit the next prelude and router-ID copy on the existing stream, wait at that already-required frontier, then finalize the pending body before using the next plan. For a terminal body, finalize after the existing epilogue wait and before adaptation/publication. When a hook is installed, retain the original immediate wait and callback ordering. On failure, drain existing work without declaring an unobserved body completed. Cancellation, deadlines and original final-publication checks remain mandatory.

This extends the existing stream and owner mechanism; it adds no executor, residency owner, cross-layer transfer issuer, new event, allocation or model/format helper. Source finish_source_dispatch checks every involved stream before releasing canonical transactions. The graph-wide owner lease remains held until final drain. Owner two-lane ready/release events remain unchanged. Root, down and ordinary launches must all use the same ordering stream, including any captured child work; verify this before code. All body pinned ID/scatter/indices/bounds spans are per-body and persist through the call. Private compact workspace is reserved once, shared across bodies and reused in stream order. Pool prepared objects already return memory in stream order; confirm no returned allocation can be freed or reused from another stream. Do not suppress generation, sampler or reader checks.

## Decision and validation boundary

The proposed change is localized scheduling with existing contracts, not a new subsystem or packet layout. It fits the owner-authorized generic prefill work and existing-pattern scope. AGENTS.md large-pattern approval remains applicable if evidence instead requires changing allocator, sampler lifetime, cross-stream ownership or a new policy owner. No such change is approved or implemented here.

Before performance, add a meaningful no-hook all-GPU numerical fixture that actually crosses two eligible bodies and exercises repeated scratch reuse. Retain existing hook/held-reader, public direct/view readers, tails, owner, overlap, cancellation/error and required-path gates unchanged. Verify actual deferred counts rather than treating enabled flags as execution. Then freeze and run a matched same-binary ABBA at original2049/64/noMTP/all-GPU settings with actual source bytes, output IDs, residency and resources. A CPU wait removed or a reported timer change is not an end-to-end gain. If a required lifetime cannot be proven, retain the existing wait and continue source attribution.

Preparation/generation/sampler-cache invalidation is a distinct larger question documented in PROGRAM-LIFETIME-20261010.md. This proposal neither solves nor bypasses it. The1700 target remains open.
