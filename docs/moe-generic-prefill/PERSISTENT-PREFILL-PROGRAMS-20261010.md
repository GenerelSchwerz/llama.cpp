## Existing contracts and why they do not preserve these programs

- llama-context.cpp:3256 selects the existing source graph variants. Row admission is bounded by output/draft width, excluding a2048-row single-slot prompt. Saved variants contain sampled mode, but lookup does not key it; mode changes currently reject caching instead.
- llama-context.cpp:2195 resets source variants during reservation. prepare_sched_reserve also invalidates captures on backing-generation changes. Both protections remain necessary.
- llama-context.cpp:4768 forces reservation on first asynchronous sampled-input entry. Server request sampler attach/detach also sets sched_need_reserve in set_sampler:4028. Disabling those invalidations without handling sampler/allocator lifetimes is unsafe.
- ggml-backend.cpp:1428 already clones schedulers while sharing the reference-counted resizable allocation plan and CPU source service. Reuse this mechanism; do not create another executor or residency owner.
- llm_graph_result::can_reuse at llama-graph.cpp:1574 checks graph parameters and every original input. Sampling input can_reuse at1395 checks actual sampler identity and state. build_sampling at5044 includes inactive dummy work, so zero public outputs alone does not prove a graph sampler-independent.
- Earlier230-234 allocation/reservation-retention probes preserved all outputs but retained three rebuilds per request and showed no useful gain. This proposal must retain compatible prepared programs, not merely larger allocations.

## Proposed implementation boundaries

Extend the existing bounded source variant cache to hold actual prefill, ordinary-input tail and sampled-input decode shapes. Use the complete execution certificate, public output shape and sampled-input mode as the selection key, followed by unchanged upstream can_reuse checks. Retain required-hybrid execution, original operators, sampling, KV/session state and canonical per-device residency. No new fusion, model predicate or specialized executor.

Separate admissible row geometry from retained-entry/CPU-region capacity. Raising the old width_limit to n_ubatch would otherwise multiply prepared CPU capacity by prompt width. Bound retained entries and aggregate private device/pinned resources; include all devices and all inactive variants. Share upstream backing only through its existing allocator plan. Account shared canonical storage once and private program/capture storage per retained entry. Resource admission or eviction must happen before allocation; unknown costs must not silently over-admit.

Make reservation compatibility include both ordinary and sampled inputs while preserving explicit refresh requests, allocator generations and retirement epochs. A changed backing generation or incompatible topology still drains and invalidates affected variants. Do not suppress shrink, retirement or generation checks to make caching appear successful. Keep the cold-start total and live high-water resources visible; a speedup purchased with retained storage must be reported as such.

Sampler attach/detach must retire every graph that references the affected sampler before its lifetime ends. A sampler-independent prompt could remain only after proving that its original graph has no such input/operation dependency. Otherwise rebuild it. Do not bypass upstream sampler can_reuse or relabel dummy sampling as independent. Parallel/staggered requests, MTP width/mode changes, cancellation and multiple devices remain requirements.

## Remaining implementation detail

- The shared resizable allocation plan already retains the maximum requirements of all scheduler plans in the same role: ggml-alloc.c:686 iterates shared->roles[role], while share_resizable_plan registers another plan at1026. This can preserve public backing through a real retained plan. No private allocator copy or suppression of shrink requests is needed. Backing generation and retirement checks still apply after replacement, eviction and borrower activity.
- A variant needs its reservation graph, reserved token/KV geometry and reservation-input mode along with its scheduler and actual graphs. Currently gf_res_reserve, sched_reserved_tokens, sched_reserved_kv and sched_need_reserve are context state, and decode calls sched_reserve before the actual certificate is available. Retaining only gf_res_prev cannot remove phase reservations safely. Selection/reservation must use the actual validated microbatch while preserving memory preparation and explicit refreshes.
- Input placement has three states: ordinary, synchronous sampled token, and asynchronous sampled inputs. place_sampled_inputs first acts on use_sampled_input and then on use_sampled_input_async. The current sampled_device bool describes only the latter. Expanded phase admission must distinguish all placement modes rather than treating synchronous sampled input as ordinary by accident.
- core_session::fits_device_budget currently checks one session, and counters expose managed device/pinned bytes only after preparation. Source program storage is allocated before the final arena/body/pool estimate, and capture preparation can grow the pool or add library workspaces. A post-allocation sum of variant counters cannot satisfy admission-before-allocation. Account each managed allocation/growth before it occurs, across split sessions, cloned schedulers and devices; release reservations only after checked disposal. Keep canonical staging/resources counted once. CUDA driver capture metadata also needs a bounded capture-count policy; it is not included in managed byte counters.
- Separate cache entry limits from admissible n_rows and prepared CPU-region limits. A2048-row prompt must not create2048 retained entries or multiply max_prepared_regions by2048. Existing upstream can_reuse remains the final topology/input authority after key selection. Explicit sampler changes retire dependent graphs; independent prompt graphs must not be lost merely because a different variant needs a sampling reservation.
