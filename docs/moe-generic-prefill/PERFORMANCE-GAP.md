## Cache loans and the budget comparison

The retained specialized port-fused-prefill-02/engine.stderr:26 reports1195 cache slots (1.91GiB) borrowed for the prompt. That is a temporary partition of its existing5GiB expert cache, not an independent extra1.91GiB allocation. prefill.h:68 defines carving prompt buffers from the cache tail; residency.cpp:101-124 unpublishes lent mappings, refills each slot's current expert from the original source after prompt DMA finishes, waits, then republishes the maps. Adaptation must be committed before lending/refill. Current generic moe-cache.cu:17391-17419 allocates two separate64MiB staging lanes and leaves the canonical residency payload allocations in place.

The native ring budget uses bytes (prefill.cpp:208-229), derived from a reference blob, then divides by the actual maximum blob size. At large chunks a host issuer streams all nonresident experts of future layers before their routes are known (2005-2010,2113-2140). Every ring reuse waits for the previous consumer's release. This deliberate extra transfer work buys copy lookahead; it is different from accurately predicting future routing. The generic demand path waits for route IDs and stages a single graph matrix bank through all waves before its next reader.

Preserved sampled whole-device peaks were10577MiB for port-fused-prefill-02 and10729MiB for flash-specialized-ids-wave-flash. These jobs differ in profile, checkpoint and MTP settings, and samples are not allocation-exclusive peaks; they do not support a speed ratio or an equal-budget claim. They do show that larger native prompt scratch must not automatically be counted as extra independent VRAM.

A complete-expert optional optimization can reuse shared graph fusion certification and matrix dispatch: certify internal gate/up and pointwise readers, retain original IDs for public auxiliary consumers, stage every required bank under a single canonical wave lease, compute the expert's down contribution, then release that wave. Nonmatching graph semantics continue through the same hybrid pipeline. A cached-buffer matcher exception alone is insufficient: ordinary paired MMQ's memory proof assumes ordinary weight allocations and no concurrent events (ggml-cuda.cu:2015-2070,8544-8554), while current bounded staging pointers are protected by canonical source/events. The shared backend must consume those actual ranges and completion leases.

If prompt workspace borrows cache bytes, the canonical owner must be the sole authority for lending, invalidation, current-occupant restoration and publication. Each device's bank allocation may be separate; the native contiguous-cache-tail pointer cannot be copied as a generic contract. MTP or parallel slots may still read a proposed bank: lease refusal or draining must happen before overwrite, and cancellation must settle every copy/reader before restoring and publishing. Never restore original profile IDs over later learned occupants. No cache-loan or complete-expert product implementation is added during CPU-only crash investigation; these are source-backed design constraints for the already requested fast-prefill work.

## Paired-source contract decision

The guarded CPU probe extracts all three pointer-selection blocks from the actual mmq.cuh. All36 direct paired cases and36 mapped first-bank cases select the expected source. Combining staged maps with the paired second bank selects18 wrong addresses; combining per-expert images with that bank selects27 wrong addresses. This is a counterexample to a proposed composition, not a bug in the current direct paired path: ggml_cuda_match_mmq_id_pair requires ordinary CUDA weight buffers, while bounded mapped launches never set x_second. All three selector branches resolve the map/image first, then overwrite x_cur with the global x_second for second-bank rows. See PREFILL-FUSION-SOURCE-AUDIT.json and containment-paired-source-contract-01/QUALIFICATION.json. The CPU-only compile/probe uses256MiB hard memory, zero swap,45s and both ordered locks; no CUDA runtime/model is loaded.

Concrete next implementation boundary: make the existing shared matrix source contract describe each paired bank's resident/staged base or per-expert image. Choose the bank before its source mapping, preserving separate physical source bases and valid ranges; share routing/input quantization only when existing backend type/layout/precision contracts agree. Canonical bounded staging must retain every bank until the last paired/activation/down reader completes. Existing graph cut/range certification must preserve original IDs and any externally retained intermediates. Keep this an optional optimization within the same pipeline, with ordinary graph arithmetic for nonmatching pairs. Do not remove the cached-buffer guard to bypass this source contract.

The existing ggml_moe_source_body::compact at ggml-moe-source-program.cpp:162-290 also reconstructs route dimensions through a local operation switch and rejects unknown operators. It is useful for currently supported optional compaction, but cannot be made a universal model-admission or whole-expert streaming requirement. General row partitioning needs graph/operator/backend semantics, or the optional optimization must decline while the unchanged shared pipeline executes that graph. Adding every future opcode to this executor-local switch would violate the goal.

This decision reuses existing source descriptors, graph certificates and canonical leases. No new residency authority, required activation/type inventory, product code or performance claim is added here. Before implementation/acceptance, the mapped-pair component needs resident/staged/image source, retained-output, cancellation and multi-device lifetime tests under bounded containment, then matched performance qualification.
